Task: "Forehead Scan" task — background video (MP4) replace karna hai, poora function detail mein samjho
Background/Context: DuckLock app mein 5 tasks hain jo user ko complete karne hote hain Reels-Lock ya App-Lock unlock karne ke liye. Inme se ek task hai jiska naam hai "Forehead Scan". Ye task ek fullscreen, landscape-mode screen hai jisme user ko ek mock YouTube-video-jaisi screen ek fixed-time tak (abhi ke hisaab se 30 seconds) dekhni hoti hai — jaise koi apne forehead ko phone se scan kara raha ho, phone ko wahi rakhe rehna hota hai. Screen ke background mein currently ek placeholder/test-ke-taur-par lagayi gayi random-animation chal rahi hai — ye humne temporarily lagayi thi jab tak asli-video ready nahi thi.
Ab kya hua hai: User ne khud ek naya video banaya hai, jiska format hum decide kar chuke hain — MP4 (WebM se better-reliability ke liye Expo/React-Native ke expo-av/expo-video components ke saath). Ye video jaan-boojh kar chhote file-size mein banaya gaya hai taaki app-performance affect na ho.
Kya-kya karna hai, detail mein:
1. Purani placeholder-animation hataake naya video lagao:
Jo bhi current-animation/video is task ki background mein chal raha hai, use poori tarah hatao aur uski jagah user ka naya MP4-video lagao. Video fullscreen hoga — poori screen cover karega, landscape-orientation mein.
2. Video quick-load/preloaded hona chahiye — koi delay visible nahi:
Jab user is task ko open kare, video turant, bina kisi loading-spinner ya fade-in ke dikhna chahiye. Ye humare app ke overall "koi bhi image/video kabhi delay se load nahi honi chahiye" wale rule ka hi ek hissa hai — is video ko bhi screen-mount hote hi ready-to-play state mein hona chahiye, screen khulne se pehle hi preload ho chuka ho agar possible ho.
3. Video ko perfectly, seamlessly LOOP karna hai:
Ye sabse zaroori technical-requirement hai. User ka source-video sirf lagbhag 20 seconds ka hai, lekin task ki total-duration abhi 30 seconds hai. Iska matlab hai ki video ko poori 30-second-duration ke dauraan kam-se-kam ek baar poora khatam hoke dobara se shuru hona padega (loop). Ye looping:
Seamless honi chahiye — matlab jab video khatam hoke restart ho, wahan koi visible-jump, freeze, black-frame, ya glitch nahi dikhna chahiye
Duration-agnostic honi chahiye — matlab agar hum future mein kabhi is task ki duration badha dein (jaise 30 seconds se badhaake 1-minute ya 2-minute kar dein), to ye looping-logic automatically, bina kisi additional code-change ke, tab bhi sahi se kaam kare — video jitni baar bhi loop karni pade, poori naye-duration ke hisaab se, wo karti rahegi
4. Existing Play/Pause button hi is video ko control karega:
Is task ke liye humne pehle se hi ek play/pause toggle-button bana rakha hai (jo already implement ho chuka hai). Wahi existing button ab is naye video ko bhi control karega — video play kare to button "play" se "pause" ho jaaye, aur agar user pause dabaye to video wahin ruk jaaye jahan thi, aur play dabane par wahin se resume ho. Koi naya alag control-button banane ki zaroorat nahi hai.
5. ⚠️ SABSE ZAROORI CHEEZ — Task complete hote hi video ko poori tarah ROKO:
Jaise hi user ye task successfully complete kar le (30-second-timer poora ho jaaye ya jo bhi completion-condition ho), ye looping-video turant automatically stop ho jaani chahiye — ideally poora video-component hi unmount ho jaaye, ya kam-se-kam shouldPlay: false/isLooping: false set ho jaaye turant.
Ye kyun critical hai: Agar aisa nahi kiya gaya, to ye video background mein permanently loop mein chalti rahegi, chahe user us screen se aage badh chuka ho — isse phone ka battery aur CPU-resource bina wajah waste hoga, aur ye ek serious performance-bug ban jaayega jo user ko pata bhi nahi chalega (kyunki screen already change ho chuki hogi, lekin peeche video chalti rahegi)
Task-completion ka event jo bhi trigger hota hai (jaise onTaskComplete callback ya navigation-event jab user next-screen par jaata hai), usi ke saath video-component ka lifecycle bhi khatam hona chahiye — dono cheezein sync mein honi chahiye
Implementation-hints (technical, agar Replit ko madad chahiye):
expo-av ke Video component ya expo-video ke VideoView component use karo
Looping ke liye isLooping={true} prop set karo (ye by-default duration-agnostic hai, kisi bhi task-duration ke saath automatically kaam karta hai, kyunki ye sirf "jab video khatam ho, phir se shuru kar do" wala simple-loop-mechanism hai)
Preloading ke liye video ko component-mount se pehle hi useRef + programmatic-load se ready-state mein le aao, ya posterSource/shouldPlay ko smartly manage karo
Task-complete hone par, jo bhi component/screen ye video render kar raha hai, use conditionally-unmount karo (jaise {!taskCompleted && <Video ... />}) — isse React khud video-component ko destroy kar dega aur playback ruk jaayegi, koi manual cleanup-code likhne ki bhi zaroorat nahi padegi is approach se
